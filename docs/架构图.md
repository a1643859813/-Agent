# Agent Runtime 架构图

```mermaid
flowchart TD
    U[用户 / CLI] --> M[main.py\n读取配置并装配依赖]

    M --> R[AgentRuntime]
    M --> S[(JsonStore\ndata/agent_state.json)]
    M --> T[ToolRegistry]
    M --> A[AsyncTaskManager]

    R -->|run(user_id, session_id, input)| C[claim_session]
    C -->|idle| L[Agent Loop\n_run_claimed]
    C -->|busy| Q[FIFO pending_inputs]
    Q -->|drain_next| L

    L --> X[_compress\n压缩过长历史]
    X --> CTX[_context\n组装模型上下文]
    CTX -->|System Prompt\n长期记忆\nSession 摘要\n最近消息| D[DeepSeekClient]
    D --> P[ToolCallParser]

    P -->|最终回答| F[写入 assistant 消息\n返回 AgentResult]
    P -->|tool_calls| E[ToolRegistry.execute]
    E --> CAL[calculator\nAST 白名单计算]
    E --> SEA[search\nmock 搜索]
    E --> TODO[todo\n会话隔离待办]
    E --> BG[background_search\n异步搜索]

    CAL --> TR[tool result / trace]
    SEA --> TR
    TODO --> TR
    BG --> A
    A --> EV[task_completed / failed / cancelled 事件]
    EV --> S
    TR --> X

    R <-->|session、todo、memory、events| S
    CTX <-->|recall Top-K| S
    F --> S
```

## 运行时关键边界

1. `AgentRuntime` 自行实现 Agent Loop；DeepSeek 只做模型推理与工具选择。
2. `JsonStore` 以 `(user_id, session_id)` 隔离短期对话、待办和事件；长期记忆按 `user_id` 存储并可跨 Session 召回。
3. 同一 Session 通过 `idle / busy` 和 FIFO 队列串行处理，避免并发修改 Context；不同 Session 可并行。
4. 每次模型调用前按固定顺序构造 Context：System Prompt → 相关长期记忆 → Session 摘要 → 最近消息与工具结果。
5. 工具结果会以 `role=tool` 回传模型；模型决定继续调用工具或返回最终答案。异步工具立即返回 `task_id`，完成事件只写回所属 Session。
